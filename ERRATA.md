# Release notes and errata

Things we found while building readers against the full public releases, where the files differ from, or go beyond, their documentation. Each reader handles these, and its module docstring has the details. Every entry was checked on the real data (November 2026). Electrode-order checks use `ibci verify-mapping` (see the README); the full audit is summarized at the end. None of this is a criticism of the releases: they are unusually well documented, and these are the gaps that only show up when you read every file.

If you are an author of one of these datasets and something here is wrong, please open an issue.

## Kunz 2025, inner speech (doi:10.5061/dryad.gf1vhhn1j)

- **Spike band power is a copy of the crossings in one file.** In `interleavedVerbalBehaviors/t12.2024.04.11_interleavedVerbalBehaviors_raw.mat`, `spikePow` equals `binnedTX` element for element (both `uint8`, values 0-20, 78% zeros); in every other T12 file spike band power has per-channel medians of 84-254 uV^2. The reader omits spike band power for this file and says so in `provenance["dropped_features"]`.
- **Negative counts stored as `uint8`.** Three T12 sequence-recall files (`t12.2023.05.16_..._joystickSeq.mat`, `t12.2023.05.16_..._joystickSingle.mat`, `t12.2023.09.19_..._lineSequenes.mat`) hold block-mean-subtracted crossings as `uint8`, so negative values wrapped around: -1 to -9, -7 and -5 respectively became 255 down to 247, 249 and 251 (20-23% of values). Read as stored, the mean is 50-58; read as `int8`, 0.04-0.08, in line with the T12 files stored as `int8` (0.03-0.05). The reader detects the empty gap between small and near-255 values, reinterprets as `int8` and records the fraction in `provenance["uint8_wraparound_fixed"]`. One repaired file (`lineSequenes`) was compared with a T12 file stored as `int8` nine days later: the same array order scores best under both scorings in every resample, with margins 0.014 / 0.029, below the 0.03 verdict threshold. The two 2023-05-16 files were not compared.
- **T12 keyword-task files use T15's array labels.** The four `chittychittybangbang` files (T12, December 2024) label their four 64-channel blocks `i6v, M1, 55b, s6v`, the names T15's files use. Every other T12 file names only `i6v` (channels 1-64) and `s6v` (65-128), and T12 has no area 4 or 55b array. Matching channel-correlation structure against other T12 files puts the block labelled `M1` at `s6v` (plain r 0.41 vs 0.24, block-centred 0.39 vs 0.23 against the interleaved task; 0.34 vs 0.19 against sentences; audit margins 0.067 / 0.075 against sequence recall in every resample). All these references are 239-435 days away, outside the 120 days the verdict rules were calibrated for, so this is strong but uncalibrated evidence. The reader labels the blocks `i6v, s6v, unnamed-1, unnamed-2` and keeps the release's labels in `provenance["release_array_labels"]`.
- **`sentenceFeatures` channels are reordered in the T12 `sentenceData` files.** In the three 2023-11-28 T12 files, `binnedTX` has 128 channels and `sentenceFeatures` 256 per feature. The crossings half of `sentenceFeatures` contains all 128 `binnedTX` channels exactly, from the go bin, but in a different order (one fixed permutation in all three files, mixing the two arrays), plus 128 channels not in `binnedTX`; its spike-power half is related to `spikePow` (r about 0.95 per channel after the same reordering) but not equal. The readme describes `sentenceFeatures` as a copy. `binnedTX` is the one in the channel order of the other T12 files (its correlation structure matches theirs). In the other 16 sentence files (T12 keyword task, T15, T16), `sentenceFeatures` equals `binnedTX` / `spikePow` from the go bin. The reader converts `binnedTX` / `spikePow` and skips `sentenceFeatures`.
- **Hidden block boundaries in four T16 sequence-recall files.** The sequence-recall files have no `blockNum`. In the four T16 files with float crossings and several blocks (`seqRecallUninstructed3ElementArrow`, `...Lines`, `seqRecallVerbalMemory`, `seqRecallVisualMemory`), the block-wise mean subtraction leaves each block's channel means' fractional parts in the data, which puts block starts at rows 6977, 13954 and 20931; each segment then has zero mean on every channel. Six trials per file span these boundaries (in three, the go window itself does), i.e. they join data from two blocks across an unrecorded gap. The reader splits these files into blocks and clips and marks the straddling trials `truncated`. In the T12 sequence-recall files (integer or `float32` storage) the boundaries cannot be recovered this way, and each file stays one Recording whose provenance says so.
- **Epochs are 1-based, inclusive**, as MATLAB indices: delay end + 1 = go start in every trial of every file, and `sentenceFeatures` row 0 is `binnedTX[go - 1]` with length `go_end - go_start + 1`. `sentenceDurations` is `go_end - go_start`, one bin less; the reader's `sentence_duration_s` keeps the release's value and says so.
- **Go windows overlap the next trial.** In the T12 keyword-task files (82-86% of trials), the T16 isolated-behaviour files (54-83%) and all T16 sequence-recall files (every trial), the go window runs into the next trial's delay period. In five T16 sequence-recall files the first trial starts before the recording and the last ends after it. The reader clips windows at block and file edges and marks them `truncated`.
- **Bin sizes.** 34 files use 10 ms bins and 33 use 20 ms. The readmes say the bin size depends on the participant, but T16 has both (10 ms for the 2024-03-04 isolated-behaviour files, 20 ms elsewhere). Two files state other values: `t12.2024.12.19_chittychittybangbang_50words_eval.mat` says 25 ms and `t16.2024.04.29_imagined_50words_eval.mat` 33 ms, against 20 ms for the other files of those sessions. Crossings per bin match the 20 ms files (T16 1.02-1.09x the session's other files, where 33 ms bins would give about 1.65x; T12 1.12x, against 1.25x for 25 ms), so 20 ms is likely. The reader keeps the stated value and flags it in `provenance["bin_size_suspect"]`.
- **Decoded text is short in one file.** `t16.2024.12.18_imagined_125kwords.mat` has 123 decoded sentences for 125 trials. The first 100 are empty (open-loop blocks 2-5), so the two missing entries belong to closed-loop block 10, but nothing in the file says which two trials they are. The reader drops that column for this file and records why in `provenance["dropped_columns"]`.
- **Array names vary within a participant.** T16 is `PEF`, `ventral6v` or `i6v`, and a 128-channel `6d` in most folders, but `PEF/55b`, `i6v`, `i6d`, `s6d` in the sequence-recall folders. The reader uses the last form throughout (originals in provenance; renamed arrays say so in their electrode locations). T15 uses `i6v, M1, 55b, s6v`; same-day comparisons with Card 2024 (2024-03-03 and 2024-06-14) match these to Card's v6v, area 4, 55b, d6v one to one (margins 0.449 / 0.452 and 0.185 / 0.191 plain / block-centred, every resample). T17 is `s6v-v`, `s6v-d` and a 128-channel `55b`.
- **`allBehaviors` files repeat the per-behaviour files.** In `isolatedVerbalBehaviors`, each participant's `*_allBehaviors_raw.mat` is the seven per-behaviour files of that session concatenated: the same blocks, with identical features and epochs, and each cue suffixed `-<behaviour>` (checked for all four participants). The readme does not mention it. Converting the folder as is would count those trials twice; the reader skips `allBehaviors` when the seven files are present. In T12's `reading` file the rest cue is blank where the other isolated-behaviour files have `DO_NOTHING`; the reader keeps it as an empty string. (Cue text is formatted differently between files, e.g. `DO_NOTHING$0` in T12's interleaved file and `(DONOTHING),` in T16's; the reader passes it through unchanged.)
- **AppleDouble files.** The zips include `__MACOSX/._*.mat` resource forks, which are not MATLAB files. The reader ignores them.

## Srinivasan 2026, speech modes and loudness (doi:10.5061/dryad.2547d7x5w)

- **Electrode order differs between files.** T15 sentence-loudness files use v6v, area 4, 55b, d6v, the order documented for Card 2024 (consistent with Card against all four references tested). For the T15 word-loudness files, the companion scripts give a different order, area 4, v6v, d6v, 55b (`using_correct_electrode_mapping = 0`, with the comment that this applies to 2023 sessions); the Dryad README does not mention it. The reader uses the scripts' order. The data are consistent with this but do not prove it: Deo 2026's T15 columns, also from 2023, match the word-loudness columns one to one (below), and against Card sessions 0-15 days from the session date given in the scripts (2023-11-04; the files carry none), Card's order scores below the best in all six (plain scoring), the scripts' order is the plain-scoring best in 3 of the 6 (margins up to 0.033), and no assignment passes the verdict rules. The reader records the evidence in `provenance["electrode_mapping_source"]`. T16's order (55b/PEF, 6v, two hand-knob arrays) comes from the companion scripts; comparisons with Deo 2026, Rigotti-Thompson 2026 and Kunz 2025 T16 data are near-ties and say nothing either way.
- **Smoothed and raw features have different lengths.** `threshcross` and `spikepow` run 3 s longer per trial than `raw_threshcross`; both start at the same time. `raw_threshcross` covers 3 s after the go cue for T15 and in T16 block 3, and 4 s in the other T16 blocks. The reader NaN-pads the raw counts and states the window in the feature description.
- **Trial timing.** Each trial array starts 1 s before the delay period; `speech_onsets` and `speech_offsets` are 30 kHz sample counts from the go cue (from the companion scripts, confirmed on the data).
- **Control trials.** Two T15 trials are cued `DO NOTHING`, which the README does not mention. Their onset values (3-5 ms after the go cue) are placeholders; the reader sets onset and offset to NaN.

## Deo 2026, whole-body mosaic (doi:10.5061/dryad.mpg4f4rg5)

- **T15 columns are probably not in Card 2024's order.** Deo names arrays with lab codes; T15's columns are `v2, v3, v1, m1`. Deo's T15 columns match Srinivasan 2026's word-loudness columns one to one under both scorings (margins 0.074 / 0.051; the match survives common-average referencing both, at a smaller margin), and both are 2023 sessions, which the Srinivasan companion scripts say used the order area 4, v6v, d6v, 55b. Against Card's sessions 0-9 days away, that order is the plain-scoring best in 5 of 6 and against Singer-Clark 2025 two days earlier, but no assignment passes the verdict rules. If Deo T15 uses that order, `v2` = area 4, `v3` = ventral 6v, `v1` = dorsal 6v and `m1` = 55b. This rests on the Srinivasan scripts, and the lab's naming is not documented (if `m1` meant primary motor cortex, it would contradict this), so it needs the authors' confirmation. Pooling Deo T15 with Card by column position may mix arrays. The reader keeps Deo's codes as array ids, gives the likely area in each T15 channel's location (marked as inferred), and records the evidence in `provenance["array_area_evidence"]`.
- **`goCue` vs `state`.** `goCue` (1-based) marks the first Go bin of `state` in every trial for T5, T11, T12, T12_control and T16. In T17 it is one bin (20 ms) earlier in every trial; in T15, in 48% of trials, evenly across blocks. The reader defines trials from `state` and keeps `goCue` as its own column.
- **Trials cut off by block ends.** 8 trials in T12_control, 3 in T15 and 7 in T17 have Go running into the end of a block, with no Return recorded. The reader keeps them, marked `truncated`.
- **`T17.mat` is MATLAB v7.3** (HDF5, matrices transposed), unlike the other files; the README says all load with `scipy.io.loadmat`. The reader handles both.
- **Array correspondence with Pun 2024.** Pun's `a1` / `a2` match Deo's `d2` / `d1` for T5 (both scorings, margins 0.18-0.21) and T11 (day 800, margins 0.057 / 0.072; inconclusive at day 658). Pun dates sessions by post-implant day and Deo by calendar date, so the 120-day check could not be applied, and the verdict rules were calibrated on T15 only.

## Rigotti-Thompson 2026, preparatory activity (doi:10.5061/dryad.brv15dvr9)

- **Arrays are not named.** The reader labels them `a1`... in channel order. In the `fig1-4` files, the channels the authors kept (firing above 2 Hz) concentrate on Deo 2026's most active channels with Rigotti-Thompson's columns taken straight (T5 and T11), which suggests `a1` / `a2` correspond to Deo's `d2` / `d1`. Channel-correlation comparisons do not settle it: against Deo T11, the plain scoring prefers the swapped order and the block-centred scoring disagrees; against Pun T11 both lean, weakly, towards the swapped order (margins 0.004 / 0.012).
- **The `delay` and `move` files of a figure hold the same trials**, as two overlapping windows. Each file is converted separately and says so in its provenance.
- **In the continuous `fig5` files, `neural_data_norm` is threshold crossings then spike band power** for the same electrodes in the same order (same-electrode correlation 0.16 for T16 and 0.39 for T11, against about 0.01 otherwise). The README lists both without saying which half is which.

## Pun 2024, recording instability / MINDFUL (doi:10.5061/dryad.n2z34tn5s)

- **`nctx` is a rate in Hz, not a count.** In T5 every value is a multiple of 50 (count per 20 ms bin x 50). In T11, 86-100% of non-zero values per block are (95-100% of all values); most of the rest lie on straight lines between neighbouring bins, consistent with linear interpolation over noise-outlier bins (the lab's `RemoveOutliers.m`).
- **`startStops` are 1-based, inclusive.** Read that way, trial length equals `timeToTarget` exactly in every block.
- **`useClick` is one value per block**, not one per trial as the README describes.
- **One block has a surplus row.** T11 day 689 block 14 has 76 rows of `trialSuccess`, `pathEfficiency` and `orthChanges` for 75 trials. In every other T11 block, success equals "acquired before the 10 s timeout"; dropping the last row restores that here (dropping the first does not). The reader drops it and records that in `provenance["trimmed_trailing_trial_rows"]`.
- **Array split not labelled.** Channels 0-95 and 96-191 behave as the two arrays (within-array correlation exceeds across-array, against an interleaved control), but which physical array is which is not stated. The reader labels them `a1` and `a2`.
- **Ages are at enrollment.** The README's ages (65 and 37) are at enrollment, years before these sessions, so they are not written as the subject's age at recording.

## Singer-Clark 2025, cursor control from speech motor cortex (doi:10.5061/dryad.prr4xgxzq)

- **Crossing threshold not stated.** The README describes an electrode-specific threshold without giving the level. The reader leaves `threshold_rms` unset.
- **`t15_day00202_words.mat` is undocumented.** The reader skips it.
- **Bin indices are 0-based** (the companion code indexes NumPy arrays with them directly).

## Card 2024, Brain-to-Text '25 (doi:10.5061/dryad.dncjsxm85)

- No discrepancies found. The documented electrode order agrees with Singer-Clark 2025's per-electrode labels on a shared recording day (2023-08-25). Not every session has a test split.

## Electrode-order audit (November 2026)

`ibci verify-mapping` over every release with a reader. A verdict needs two scorings to agree (plain correlation-structure matching, and the same after subtracting each array-pair block's mean), each with margin >= 0.03 and bootstrap support >= 0.95, with the reference within 120 days when dates are known. What that calibration does and does not show:

- It was run on 1,215 T15 comparisons (Card 2024 against itself, 990 pairs; Singer-Clark 2025 and Srinivasan 2026 against Card, 225), on point estimates, with the thresholds chosen on the same data. It gave no false verdicts and 483 correct ones (462 within 120 days, 21 undated), all for correct claimed orders. For 90 of these comparisons (Srinivasan) the reference answer is itself inferred.
- So it shows the rule rarely asserts a wrong answer for T15. It has not been shown to detect a known mismatch in real data, and other participants are outside it. In a later check, unrelated data (Deo 2026 T16 labelled as T15) produced no verdict against any of 45 Card sessions.
- The bootstrap resamples time within each recording. It does not capture variation between days or between releases, which is larger.
- An earlier version also *rejected* a claimed order that trailed the best by >= 0.03 under both scorings. It no longer does: it fired on data with no usable channel identity (Deo T16 labelled as T15: 18 of 26 Card sessions within 120 days), and for Srinivasan word-loudness it rejected both candidate orders against different references. How far the claimed order trails is still reported, as a diagnostic.
- The block-centred scoring was added after the plain scoring gave a confident answer (Rigotti-Thompson T11 vs Deo T11, margin 0.100) that two indirect checks contradict (see above); preprocessing that changes each array's overall correlation strength can drive the plain scoring.

Where files of one release were compared with each other (Card 2024, Pun 2024), the tool found no disagreement; the Kunz 2025 within-release checks were inconclusive. Srinivasan 2026's word-loudness files use a different order from its sentence-loudness files, according to its companion scripts. Kunz 2025's T15 order matches Card's. T16's array order across releases is unresolved: in every T16 comparison several orders score almost the same, including between Kunz 2025 files that name their arrays identically, so the method cannot tell T16's arrays apart. Singer-Clark day 468 relies on its per-electrode labels. ("Matched" means the assignment passed the rules but the releases name arrays differently, so there is no claimed order to compare.) ## Dryad downloads (all datasets)

- Dryad answers file downloads with a redirect to a pre-signed S3 URL. A client that forwards its `Authorization` header to S3 gets HTTP 400. `ibci_datasets.dryad` drops the token on cross-host and non-HTTPS redirects.
